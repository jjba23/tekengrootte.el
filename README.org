/tekengrootte/ means character size in the Dutch language.

Proportionally sized face sizes for Emacs.  Instead of hard-coding a face height, you
express it as a multiple of one adjustable scale; changing the scale then resizes every
face that was set up that way.

[[https://jointhefreeworld.org/static-assets/other/img/tekengrootte-2025-11-20-12-34-42.png]]

For example, you could semantically say that you want ~org-level-1~ headers to be ~1.3x~
the scale.  The scale itself is picked from a range of names, from ~nano~ to ~colossal~.
All values are entirely customizable and should be tweaked to your needs.

* How it works
:PROPERTIES:
:CUSTOM_ID: how-it-works
:END:

Two things do the work:

- ~tekengrootte-mk-font-size~ returns a height scaled by the current scale, so it can be
  used directly in the ~:height~ face attribute.  Relative heights stay floats, while
  absolute heights (integers, such as ~114~) are rounded back to integers.
- ~tekengrootte-set-scale~ switches the current scale to one of the names in
  ~tekengrootte-sizes~ and then runs ~tekengrootte-set-scale-hook~.

Faces are *not* re-applied by the package itself; hook your face-setting function to
~tekengrootte-set-scale-hook~ and every face is refreshed when the scale changes.

* Ways to install
:PROPERTIES:
:CUSTOM_ID: ways-to-install
:END:

/Four routes to the same 0.4.4, from the most automated to the most manual.  They all build the tag this README documents./

** From the Guix channel
:PROPERTIES:
:CUSTOM_ID: from-the-guix-channel
:END:
*GNU Guix* is the functional package manager this project is developed with: a build is a pure function of its inputs, so the same recipe gives the same result everywhere, and an upgrade that goes wrong can be rolled back.

The jointhefreeworld channel carries ~emacs-tekengrootte~, so a checkout of the channel is enough — no package definition to write:

#+begin_src shell
git clone https://codeberg.org/jjba23/guix-jointhefreeworld.git
guix install -L ./guix-jointhefreeworld emacs-tekengrootte
#+end_src

Add the channel to ~$HOME/.config/guix/channels.scm~ (the channel's README has the four lines) and a plain ~guix install emacs-tekengrootte~ keeps working on every later ~guix pull~.

** From the Nix flake
:PROPERTIES:
:CUSTOM_ID: from-the-nix-flake
:END:
*Nix* offers the same declarative, reproducible model with its own language, its own store and a binary cache, and it is a natural fit if the rest of your machine is already described in Nix.

The jointhefreeworld flake builds this project with this repository's own expression, so the package cannot drift from the source:

#+begin_src shell
nix build github:jjba23/nix-jointhefreeworld#emacs-tekengrootte
#+end_src

The same attribute is available as an overlay, so ~pkgs.jointhefreeworld.emacs-tekengrootte~ works inside a NixOS or home-manager configuration too.

** As a container image
:PROPERTIES:
:CUSTOM_ID: as-a-container-image
:END:
*Podman or Docker* is the route that puts nothing on the host: the ~Dockerfile~ in this repository builds the project in a builder stage and copies only what it installed into a runtime stage, so the image is small and the host keeps its own toolchain untouched.

#+begin_src shell
podman build -t tekengrootte-el .   # docker build -t tekengrootte-el . also works
podman run --rm -it tekengrootte-el
#+end_src

The image's entry point is Emacs, with tekengrootte.el installed and byte-compiled, which makes it useful for a quick try and for reproducing a bug on a clean system.

** As a distribution package
:PROPERTIES:
:CUSTOM_ID: as-a-distribution-package
:END:
*Debian, openSUSE and Arch* each get the project through their own package manager.  Packaging lives in this repository under ~packaging/~ and is pinned to the same release tag, so the recipes and the sources they build are versioned together.

None of the three archives ships tekengrootte.el yet, so these are recipes to build rather than packages to install from a mirror:

| Distribution   | Package              | How to build it                                                                     |
|----------------+----------------------+-------------------------------------------------------------------------------------|
| Debian, Ubuntu | ~elpa-tekengrootte~  | copy ~packaging/debian~ to the repository root, then ~dpkg-buildpackage -us -uc -b~ |
| openSUSE       | ~emacs-tekengrootte~ | ~osc build~ with ~packaging/opensuse~                                               |
| Arch           | ~emacs-tekengrootte~ | ~makepkg -si~ in ~packaging/arch~                                                   |

Each recipe carries its own dependency list, so a missing library fails the build with its name rather than producing a package that cannot load.

** Which one?
:PROPERTIES:
:CUSTOM_ID: which-one
:END:
- *Guix* if you want the toolchain the project is tested with, and the ability to roll back a bad upgrade.
- *Nix* if the rest of your machine is already declarative; the flake pins nixpkgs and gives you a binary cache.

* Installing
:PROPERTIES:
:CUSTOM_ID: installing
:END:

This package is not (yet) available in popular Emacs repositories such as MELPA or ELPA.
An example installation with Elpaca:

#+begin_src emacs-lisp
  (defun my/set-faces ()
    "Set my face heights relative to `tekengrootte-scale'."
    (interactive)
    (set-face-attribute 'default nil
                        :height (tekengrootte-mk-font-size 114))
    (set-face-attribute 'fixed-pitch nil
                        :height (tekengrootte-mk-font-size 114))
    (set-face-attribute 'variable-pitch nil
                        :height (tekengrootte-mk-font-size 1.2))
    (set-face-attribute 'org-level-1 nil
                        :height (tekengrootte-mk-font-size 1.3)))

  (use-package tekengrootte
    :ensure (:host github :repo "jjba23/tekengrootte.el" :branch "trunk")
    :bind (("C-c f c" . tekengrootte-set-scale-colossal)
           ("C-c f j" . tekengrootte-set-scale-jumbo)
           ("C-c f x" . tekengrootte-set-scale-larger)
           ("C-c f l" . tekengrootte-set-scale-large)
           ("C-c f r" . tekengrootte-set-scale-regular)
           ("C-c f s" . tekengrootte-set-scale-small)
           ("C-c f t" . tekengrootte-set-scale-tiny)
           ("C-c f n" . tekengrootte-set-scale-nano)
           ("C-c f +" . tekengrootte-set-scale-increase)
           ("C-c f -" . tekengrootte-set-scale-decrease)
           ("C-c f 0" . tekengrootte-set-scale))
    :hook (tekengrootte-set-scale-hook . my/set-faces)
    :config
    (my/set-faces))
#+end_src

Without ~use-package~ the same setup reads:

#+begin_src emacs-lisp
  (require 'tekengrootte)
  (add-hook 'tekengrootte-set-scale-hook #'my/set-faces)
  (my/set-faces)
#+end_src

It is also packaged with Nix. This repository carries the expression itself, ~default.nix~ next to ~tekengrootte.el~, so ~nix-build~ in this checkout builds the package; and it is part of [[https://codeberg.org/jjba23/nix-jointhefreeworld][nix-jointhefreeworld]], the set of Nix packages for everything Jointhefreeworld. The set's ~emacsOverlay~ adds it to ~emacsPackages~, byte-compiled and with its autoloads, so an Emacs that Nix builds gets it the way it gets any other package:

#+begin_src nix
  let
    emacsPackages = pkgs.emacsPackages.overrideScope nix-jointhefreeworld.emacsOverlay;
  in
    emacsPackages.withPackages (epkgs: [ epkgs.tekengrootte ])
  #+end_src

* Usage

** Changing the scale
:PROPERTIES:
:CUSTOM_ID: changing-the-scale
:END:

Every size has its own command, so it can be bound to a key:

#+begin_src emacs-lisp
  (global-set-key (kbd "C-c f l") #'tekengrootte-set-scale-large)
#+end_src

Or call ~tekengrootte-set-scale~ interactively, which asks for a size with completion
(~M-x tekengrootte-set-scale~), and therefore also works for sizes you added yourself:

#+begin_src emacs-lisp
  (tekengrootte-set-scale 'jumbo)   ; programmatically
  (call-interactively #'tekengrootte-set-scale) ; asks for a size
#+end_src

Asking for a size that does not exist signals a ~user-error~ and leaves the current scale
untouched.

Two commands step one size at a time, which is what a key binding usually wants:
~tekengrootte-set-scale-increase~ and ~tekengrootte-set-scale-decrease~.  They go to the
nearest size above or below the current scale, so they keep working after you edit
~tekengrootte-sizes~ or set the scale by hand, and at the largest or smallest size they say
so and change nothing.

#+begin_src emacs-lisp
  (global-set-key (kbd "C-c f +") #'tekengrootte-set-scale-increase)
  (global-set-key (kbd "C-c f -") #'tekengrootte-set-scale-decrease)
#+end_src

:END:

| Command                           | Size             | Default multiplier |
|-----------------------------------+------------------+--------------------|
| ~tekengrootte-set-scale-colossal~ | ~colossal~       |                1.5 |
| ~tekengrootte-set-scale-jumbo~    | ~jumbo~          |                1.4 |
| ~tekengrootte-set-scale-larger~   | ~larger~         |               1.25 |
| ~tekengrootte-set-scale-large~    | ~large~          |               1.15 |
| ~tekengrootte-set-scale-regular~  | ~regular~        |               1.05 |
| ~tekengrootte-set-scale-small~    | ~small~          |                0.9 |
| ~tekengrootte-set-scale-tiny~     | ~tiny~           |                0.8 |
| ~tekengrootte-set-scale-nano~     | ~nano~           |                0.7 |
| ~tekengrootte-set-scale-increase~ | the next size up |                  – |
| ~tekengrootte-set-scale-decrease~ | the next size down |                – |
| ~tekengrootte-set-scale~          | any of the above |                  – |

* Customizing
:PROPERTIES:
:CUSTOM_ID: customizing
:END:

All of the following are custom options, available through
~M-x customize-group RET tekengrootte~.

** ~tekengrootte-sizes~
:PROPERTIES:
:CUSTOM_ID: tekengrootte-sizes
:END:

An alist of size names and their multipliers.  Add, remove or retune entries to taste:

#+begin_src emacs-lisp
  (setq tekengrootte-sizes
        '((nano . 0.7)
          (tiny . 0.8)
          (small . 0.9)
          (regular . 1.05)
          (large . 1.15)
          (larger . 1.25)
          (jumbo . 1.4)
          (colossal . 1.5)
          (gigantic . 1.8)))
#+end_src

New names are immediately usable with ~M-x tekengrootte-set-scale~ (they are offered
sorted by multiplier).  Entries whose value is not a number are ignored.  Note that the
per-size commands listed above are fixed: pick a size with ~tekengrootte-set-scale~, or
bind a lambda, if you add your own names.

** ~tekengrootte-scale~
:PROPERTIES:
:CUSTOM_ID: tekengrootte-scale
:END:

The multiplier currently in use, initially ~1.1~.  Set it through
~tekengrootte-set-scale~ rather than ~setq~, so that ~tekengrootte-set-scale-hook~ runs.
Customize takes the same path: setting the value in ~M-x customize-group RET tekengrootte~
runs the hook too, and only when the value really changed.

** ~tekengrootte-set-scale-hook~
:PROPERTIES:
:CUSTOM_ID: tekengrootte-set-scale-hook
:END:

Hook run after the scale changed.  Use it to re-apply the faces created with
~tekengrootte-mk-font-size~, as in the installation example above.

* Development
:PROPERTIES:
:CUSTOM_ID: development
:END:

The tasks live in [[./maak.scm][maak.scm]] and are run with [[https://codeberg.org/jjba23/maak][maak]]:

#+begin_src shell
  maak           # the whole gate: version, clean, lint, then test
  maak lint      # byte-compile with warnings as errors, then checkdoc
  maak test      # ERT test suite
  maak compile   # byte-compile the package and its tests
  maak clean     # remove the *.elc files
  maak repl      # an Emacs with tekengrootte loaded
  maak --list    # every task
#+end_src

The version is written by hand once, in the ~Version:~ header of ~tekengrootte.el~, which
is where Emacs and ~default.nix~ read it.  The spec, the PKGBUILD, the README and the
Debian changelog cannot read that header, so they carry copies, and these tasks keep them
in step:

#+begin_src shell
  maak version                # print the version the header declares
  maak version-check          # fail unless every copy agrees with it
  maak sync-version [VERSION] # write VERSION (or the header's) into every copy
  maak pkgsums                # rewrite the Arch checksum from the release archive
#+end_src

~maak check~ runs ~version-check~ first, so a tree whose copies disagree cannot pass the
gate.  A release is ~maak sync-version 0.2.3~, then the release notes and the wording of
the new changelog entry, a commit, a ~v0.2.3~ tag, and finally ~maak pkgsums~ once the tag
is pushed: the Arch checksum comes from the archive the forge makes from that tag, so it
cannot be written any earlier.

~maak lint~ is a real gate: ~checkdoc-file~ only reports findings and always exits 0, so
[[./test/tekengrootte-checkdoc.el][test/tekengrootte-checkdoc.el]] counts them and exits non-zero when there is at least one.
Set ~EMACS~ to compile and test with another Emacs, as in ~EMACS=emacs-29 maak check~.

The same gate runs in CI: [[file:.github/workflows/check.yml][.github/workflows/check.yml]] spells the ~lint~ and
~test~ commands out for a plain Emacs, so it needs no Guile, and runs them on every push and
pull request against two Emacs versions.  It also fails when a formatter has put a space
into an autoload cookie (~;;; ###autoload~), which turns the cookie into a plain comment and
silently stops the command from being autoloaded.

A single test can be run from Emacs with:

#+begin_src emacs-lisp
  (load-file "test/tekengrootte-tests.el")
  (ert-run-tests-interactively "tekengrootte-tests-set-scale")
#+end_src

** 0.4.0 (2026-11-07)
:PROPERTIES:
:CUSTOM_ID: 0-4-0
:END:

- Relicensed from GPL-3.0-or-later to MIT.  ~LICENSE~ carries the MIT text and
  every header, packaging recipe and package label names MIT.
- New commands ~tekengrootte-set-scale-increase~ and
  ~tekengrootte-set-scale-decrease~ step to the nearest size above or below the
  current scale, which is what a key binding usually wants.
- Setting ~tekengrootte-scale~ through Customize now runs
  ~tekengrootte-set-scale-hook~, as ~tekengrootte-set-scale~ always did.
- Added a GitHub Actions workflow that runs the byte-compile, checkdoc and ERT
  gate on every push and pull request.
- Moved to GitHub: the Codeberg repository is archived, so the package headers,
  the packaging recipes and the installation examples now name
  [[https://github.com/jjba23/tekengrootte.el][github.com/jjba23/tekengrootte.el]].

** 0.2.0
:PROPERTIES:
:CUSTOM_ID: 0-2-0
:END:

- ~tekengrootte-set-scale~ signals a ~user-error~ for unknown size names instead of
  silently setting ~tekengrootte-scale~ to ~nil~, which used to break every following
  call to ~tekengrootte-mk-font-size~.
- ~tekengrootte-set-scale~ reads its size with completion when called interactively.
- ~tekengrootte-mk-font-size~ rounds integer heights, so absolute sizes such as ~114~
  stay valid ~:height~ values.
- ~tekengrootte-mk-font-size~ is no longer an interactive command.
- The meaningless ~(t . 1.1)~ entry was dropped from ~tekengrootte-sizes~.
- All commands are autoloaded, so key bindings work before the package is loaded.
- Added an ERT test suite, maak tasks and proper package headers.
